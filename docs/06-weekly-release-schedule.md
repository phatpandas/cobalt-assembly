# Cobalt Assembly — Weekly Release Schedule

## Release principle

Cobalt Assembly should publish with the discipline of a premium product house: one clear customer-visible advance each week, supported by a focused tool improvement and an editorial artifact that explains the value.

The release system is designed to create compounding product depth without exhausting the audience or fragmenting the catalog.

## Sustainable weekly cadence

| Day | Release activity | Purpose |
|---|---|---|
| Monday | Signal review and release-note preparation | Choose one customer problem and define evidence of improvement |
| Tuesday | Headline product release or meaningful template upgrade | Deliver a visible system advance |
| Wednesday | Tool improvement or new focused feature | Increase recurring workflow value |
| Thursday | Content drop and workflow demonstration | Teach the method behind the release |
| Friday | Product story, customer education, and insight capture | Distribute the release and collect qualitative learning |

Every release should have one outcome, one proof artifact, one supporting piece of content, and one natural next product.

## Release packaging standard

Every customer-visible release contains:

1. A concise release name and outcome statement.
2. A light-mode product preview or annotated workflow.
3. A short release note explaining what changed and why it matters.
4. One content artifact: field note, lesson, guide excerpt, or workshop.
5. One contextual continuation into the next template, tool, or content product.

## Release tiers

| Tier | Cadence | Examples |
|---|---|---|
| Headline release | Weekly | New template, meaningful tool capability, flagship content module |
| Capability improvement | Weekly or biweekly | Better output structure, workflow shortcut, accessibility improvement |
| Editorial signal | Weekly | Field note, workflow demonstration, release commentary |
| Seasonal synthesis | Quarterly | Assembly Review, ecosystem roadmap, curated bundle refresh |

## Quality gates

Before a release becomes public, verify:

- The customer outcome is legible in one sentence.
- The associated page contains live proof, not generic claims.
- The relevant template, tool, and content pathway is connected.
- Visual treatment conforms to the blue/silver/white system.
- Motion clarifies a state or workflow.
- Support, accessibility, and update notes are ready.
- The release does not depend on false scarcity or unverified customer claims.

## Distribution rhythm

```text
Release note
  → Product-page update
  → Library workflow article
  → Segmented email message
  → Social/editorial application
  → In-product update for active customers
  → Qualitative insight review
```

The twelve-week sequence repeats as a seasonal system: retain the structure, refresh the customer problem, and deepen the most-adopted pathways.
